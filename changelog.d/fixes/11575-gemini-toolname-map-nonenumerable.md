- **fix(translator):** MCP tool calls through Gemini/Antigravity no longer fail with `No such tool available`. The tool-name alias ledger (`_toolNameMap`) that lets the response translator turn the sanitized wire name `mcp_chrome_devtools_list_pages` back into the caller's `mcp__chrome-devtools__list_pages` was published as an _enumerable_ property. A `Map` has no JSON form, so it serialized into the upstream body as a bare `{}` and returned from the executor's capture round trip as `{}` rather than a `Map` — every alias was silently dropped and the mangled name reached the client (colliding names arrived as an opaque `tool_<hash>`). It is now attached non-enumerably via `attachToolNameMap()` on the openai-to-gemini, claude-to-gemini, openai-to-claude and Antigravity Cloud Code envelope paths, matching the contract `openai-responses.ts` already followed ([#4091](https://github.com/diegosouzapw/OmniRoute/issues/4091) / [#4307](https://github.com/diegosouzapw/OmniRoute/issues/4307) parity). Also stops a stray `"_toolNameMap":{}` being sent upstream on every tool-bearing request. Regression guard: `tests/unit/gemini-toolname-map-enumerable-round-trip.test.ts`. ([#11575](https://github.com/diegosouzapw/OmniRoute/pull/11575))
